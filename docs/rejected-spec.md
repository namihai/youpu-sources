# Rejected 规范

## 定义

`rejected/rejected.csv` 用于记录已确认不保留的数据集来源。

拒绝原因可能包括但不限于：

- 链接失效
- 不是数据集来源
- 来源不真实
- 无法访问
- 无法验证有效性
- 与已有记录重复
- 权限或可用性不符合收录要求

## 文件形式

- rejected 只维护一个 CSV 文件：`rejected/rejected.csv`
- 每一行代表一个已拒绝来源

## 字段定义

CSV 头应固定为：

```csv
url,title,reason
```

字段说明：

- `url`：规范化后的 `canonical_url`，作为唯一标识
- `title`：来源标题或人工识别名称
- `reason`：拒绝原因

## url 规范

`url` 应填写规范化后的 `canonical_url`，遵循以下原则：

- 使用稳定主链接
- 去掉追踪参数，例如 `utm_*`
- 去掉无意义 query 参数
- 去掉页面锚点
- 对同一资源的多个跳转链接，尽量统一到同一个主链接

同一个 `canonical_url` 在 `rejected.csv` 中不应重复出现。

## reason 填写建议

`reason` 应简洁明确，优先写结论，不写长篇过程。

推荐风格：

- `链接失效，页面已无法访问`
- `不是数据集来源，仅为资讯文章`
- `与 accepted 中已有来源重复`
- `需授权且无公开申请路径`
- `页面存在，但无法确认实际数据存在`

不推荐风格：

- 过长的调查过程
- 带大量个人工作流细节的描述
- 模糊表达，例如“感觉不太对”

## 后续校验建议

后续自动化工具可校验：

- CSV 列名是否正确
- `url` 是否为空
- `url` 是否重复
- 每行字段数是否一致
