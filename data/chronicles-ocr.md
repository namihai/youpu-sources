# 跨时代汉字视觉感知评测基准（Chronicles-OCR）
## 亮点
- 评估视觉语言模型处理不同历史字体和载体的能力
- 图像规模：2,800张
- 字体范围：甲骨文、金文、篆书、隶书、楷书、行书、草书
- 数据大小：1.41 GB
- 许可协议：Apache-2.0
- URL：https://huggingface.co/datasets/VirtualLUO/Chronicles-OCR/tree/main
## 数据内容
Chronicles-OCR涉及七种汉字书写形态：
| 字体 | 主要视觉特点 |
|---|---|
| 甲骨文 | 笔画细锐、构形不统一、布局自由 |
| 金文 | 线条较圆厚，常与青铜器背景结合 |
| 篆书 | 结构趋于规范，曲线和对称性明显 |
| 隶书 | 字形扁平，出现明显笔画规范化 |
| 楷书 | 方块结构和笔画边界相对稳定 |
| 行书 | 笔画连写、简化和局部变形 |
| 草书 | 连写程度高，单字边界可能难以区分 |

其中，甲骨文、金文和篆书被归入古文字阶段；隶书、楷书、行书和草书归入相对成熟的书写阶段。
## 阶段自适应标注
数据没有强制七种字体采用完全相同的标注粒度，而是根据不同历史阶段的视觉特点选择标注方式。
### 1. 古文字阶段
甲骨文、金文和篆书采用较细的字符级标注，主要包括：
* 单字边界框；
* 古文字到现代汉字的映射；
* 未释字或无法确定字符标记；
* 句子或段落阅读顺序；
* 原始图像和字体类别。

古文字中的未知字符使用类似`[UNK]`的占位形式。该设计可以保留未释读内容，避免为了获得完整文本而强行赋予现代汉字标签。
### 2. 成熟字体阶段
隶书、楷书、行书和草书主要采用段落级标注：
* 整体转写文本；
* 原始阅读顺序；
* 字体类别；
* 图像路径及相关元数据。

原因在于成熟字体通常具有较完整的连续文本，而草书和行书中的单字边界可能不稳定，逐字符边界框未必适合所有样本。
## 四项评测任务
| 任务 | 覆盖字体 | 指标 |
|---|---|---|
| 跨时代字符定位 | 甲骨文、金文、篆书 | IoU阈值0.75下的F1/H-mean |
| 古文字细粒度识别 | 甲骨文、金文、篆书 | Exact Match准确率 |
| 古代文本解析 | 七种字体 | 1 − 归一化编辑距离 |
| 字体分类 | 七种字体 | 分类准确率 |

### 1. 跨时代字符定位
要求模型在复杂历史图像中找到字符，并正确输出相应内容。它同时测试空间定位和字符识别。
### 2. 古文字细粒度识别
通过视觉指代方式明确指出目标字符，让模型识别对应的现代汉字，从而减少“找不到目标位置”对识别结果的影响。
### 3. 古代文本解析
要求模型按照正确顺序转写整幅图像中的文字。该任务需要处理：
* 竖排或多列布局；
* 阅读方向；
* 草书连写；
* 碑刻和拓片噪声；
* 字符缺损与未知字符。
### 4. 字体分类
判断图像属于甲骨文、金文、篆书、隶书、楷书、行书或草书。该任务主要测量宏观风格和载体感知能力。
## 数据结构
官方推荐的数据目录如下：
```
data/
├── Chronicles_OCR.jsonl
└── images/
    ├── 甲骨文/
    ├── 金文/
    ├── 篆书/
    ├── 隶书/
    ├── 楷书/
    ├── 行书/
    └── 草书/
```
核心记录至少围绕以下信息组织：
```
样本
├── image_path
├── font_type
├── annotation
├── 字符级边界框（古文字）
├── 现代汉字映射（古文字）
├── 阅读顺序或段落转写
└── 未释字标记
```
仓库同时提供：
* 模型推理脚本；
* 基于规则的评分脚本；
* 结果汇总脚本；
* OpenAI兼容接口和本地vLLM推理方式；
* 基准排行榜。
