# 甲骨文可语义数据集（PD-OBS）
## 亮点
- 将甲骨文图像、现代汉字、古文字形体、部首结构和象形含义组织在一起，主要服务于可解释甲骨文考释。
- 字典字符：47,157个
- 现代楷书图像：47,157张
- 古文字图像：10,968张
- 甲骨字图像条目：11,739个，包含重复字形
- 与甲骨字关联的唯一字符：3,173个
- 数据获取：Google Drive
- URL：https://github.com/PKXX1943/PD-OBS
## 数据规模
“47,157”代表《康熙字典》候选字符条目总数，并不代表47,157张甲骨字图像。
| 数据组成 | 数量 |
|---|---:|
| 字典字符 | 47,157 |
| 现代楷书图像 | 47,157 |
| 有古文字图像的字符 | 10,968 |
| 古文字图像 | 10,968 |
| 有甲骨字图像关联的唯一字符 | 3,173 |
| 甲骨字图像条目 | 11,739，含同字不同字形或重复类别 |

因此，PD-OBS更接近“47,157条汉字知识字典，部分条目附有古文字和甲骨字图像”。其甲骨文视觉覆盖范围约为3,173个现代字符映射。
## 数据来源
| 数据部分 | 来源 |
|---|---|
| 字符候选集合 | 《康熙字典》 |
| 字义、部首和《说文解字》内容 | 汉典等数字字典 |
| 现代楷书图像 | 汉典 |
| 古文字图像 | 古文字诂林/开放古文字字形数据库 |
| 甲骨字图像 | HUST-OBC与EVOBC |
| 补充与总结文本 | GPT-4.1生成后复核 |

## 数据结构
README公布的目录为：
```
PD-OBS/
├── dictionary/
│   ├── dictionary.json
│   └── id_to_char.json
└── img/
    ├── regular/
    ├── ancient/
    └── obs/
```
各部分含义如下：
* `dictionary.json`：字典定义、部首分析和象形分析；
* `id_to_char.json`：内部ID到汉字的映射；
* `img/regular/`：现代楷书字形图像；
* `img/ancient/`：古文字或古隶字形图像；
* `img/obs/`：甲骨文字形图像。

这一结构比纯分类文件夹更适合多模态模型，但README没有公布JSON字段示例、缺失值处理方法和一字多图的具体关联格式。

## 标注生成流程
PD-OBS的文本标注经过三个阶段：
### 1. 字典信息抽取
从《说文解字》及相关数字字典中提取：
* 部首；
* 字义；
* 释义；
* 构形说明；
* 古文字相关解释。
### 2. 模型补充与总结
作者使用GPT-4.1结合字形图像：
* 补充部首标签；
* 总结部首语义；
* 生成或整理象形分析；
* 将传统字典描述转化为模型训练所需的问答文本。
### 3. 自动检查与人工复核
* 使用GPT-4.1进行自动自检；
* 人工修正不规范或偏离实际字义的标签；
* 最终形成部首分析和象形分析文本。

这意味着PD-OBS中的分析文本具有“字典材料＋模型生成＋人工复核”的混合性质。它们不能全部视为古文字专家逐条原创标注。
